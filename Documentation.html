TelegramFreeRich

Design Specification — v4.0 (as shipped)
Last updated: July 2026

A desktop WYSIWYG rich text editor for Telegram Bot API 10.1.

Send structured, formatted messages through any Telegram bot. No Premium required.

1. What

A desktop WYSIWYG editor for Telegram rich messages. User types visually, sees a live preview, and sends via sendRichMessage (Bot API 10.1, June 2026). No code visible. No Premium subscription needed.

2. Audience

Anyone who wants to send professionally formatted Telegram messages without paying for Premium. Telegram locked rich text editing to Premium users, but Bot API 10.1 gives bots the same capability for free. This app bridges that gap.

3. Architecture

Rejected

contenteditable DOM → Markdown string → sendRichMessage(markdown)

The API does not accept a Markdown string for complex blocks. It expects a structured JSON array of InputRichBlock* objects.

Shipped

TipTap (ProseMirror) DOM → Block State (JSON[]) + inline segments → sendRichMessage(blocks)

Every message section is an independent block object in an array. Inline runs inside a block are parsed separately into { text, marks[], href? } segments and serialized into nested RichText* objects as the block's rich_text field, so bold / spoiler / link formatting survives the trip to the API instead of being flattened to plain text.

src/renderer/components/useTfrEditor.js   TipTap instance + extensions
src/renderer/lib/editor-actions.js        one registry for every command
src/shared/block-parser.js                DOM        -> Block State
src/shared/inline-parser.js               inline DOM -> styled segments
src/shared/block-serializer.js            Block State -> Telegram JSON

Block Structure Example

[
  { "type": "heading", "level": 2, "text": "Title" },
  { "type": "paragraph", "text": "Text with bold and a link",
    "rich_text": [
      { "type": "text", "text": "Text with " },
      { "type": "bold", "text": { "type": "text", "text": "bold" } },
      { "type": "text", "text": " and a " },
      { "type": "link", "url": "https://t.me/x",
        "text": { "type": "text", "text": "link" } }
    ] },
  { "type": "preformatted", "language": "js", "text": "console.log('hi')" },
  { "type": "table", "header": ["Col A", "Col B"], "rows": [["1", "2"]] },
  { "type": "list", "style": "bullet", "items": ["Item 1", "Item 2"] },
  { "type": "details", "summary": "Expand", "content": "Hidden content" },
  { "type": "photo", "url": "https://...", "caption": "" },
  { "type": "divider" },
  { "type": "footer", "text": "Footnote 1" }
]

Each block maps to its equivalent InputRichBlock* class at send time.

4. Critical: Checklist is Separate from Rich Message

FeatureAPISend Method
Text, lists, tables, media, math, footnotes, etc.Rich MessagesendRichMessage with InputRichMessage
Checklist (done/todo)ChecklistsendChecklist with InputChecklist

UI implication: When the user clicks "Checklist", the app must call a separate API (sendChecklist), not include it in the Rich Message block array. If the user wants both rich text and a checklist in one "message", two separate API calls must be made. This must be visually clear in the UI.

7. UI Layout

The window mirrors Telegram Desktop's own rich-text composer: a frameless dark window, hairline-outlined pill buttons, violet Premium stars, and one salmon send button.

Toolbar

  1. History: undo, redo
  2. Aa (text style): regular text, H1-H6, quote, pull quote, code block, footer, collapsible, divider, right-to-left message
  3. B (formatting): bold, italic, underline, strikethrough, spoiler, highlight, monospace, subscript, superscript, clear formatting
  4. Lists: bulleted, numbered, checklist (labelled "sent as sendChecklist" - see Section 4)
  5. Table: insert 3x3, add/delete row and column, delete table
  6. Link, Media, Formula: link toggle; image from URL or file, video, audio, slideshow, collage, location; block and inline math
  7. Emoji: searchable picker with a category strip

The violet star marks features Telegram gates behind Premium. Every menu and the insert palette are generated from a single action registry, so a new command is declared once.

Bottom Bar

  • Wand button opens the insert palette - a searchable list of every block and inline format
  • Character counter (32,768 limit) appears once the message is not empty
  • Trash clears the message after an in-app confirmation
  • Send posts the message; right-click chooses rich message / draft / edit

Live Preview

Collapsible right panel, Telegram-style message bubble:

  • Rendered as React elements from Block State - never innerHTML
  • Shows headings, quotes, tables, checklists, galleries, maps, spoilers and inline math
  • Reports the block count, so the API payload shape is visible while writing

Settings (gear in the title bar, or Ctrl+,)

  • Bot Token (from @BotFather) - encrypted by the OS keychain in the main process
  • Chat ID (channel or group) and the message ID used by Edit mode
  • "Test Connection" button - calls getMe before any real send
  • Language (English / Persian) and theme (dark / light)

9. Decisions and Open Questions

Decided

  • UI language: bilingual (English + Persian). Choosing Persian mirrors the whole window to RTL; a message can also carry its own is_rtl flag independently.
  • Drafts: exposed as a send mode (sendRichMessageDraft) rather than local files - the 30-second server-side preview is what Telegram actually provides.
  • Credentials: the bot token goes straight to the main process and is encrypted with safeStorage; the renderer only learns whether a token exists. Chat ID and the edit target are stored the same way, never in plain localStorage.
  • Editor model: one ProseMirror document instead of Notion-style draggable cards. The block array is derived from the document at send time, which keeps typing, selection and undo behaving like Telegram's own composer.

Still open

  • Size and quantity limits for slideshow and collage media are undocumented by Telegram.
  • Custom emoji (RichTextCustomEmoji) requires an uploaded emoji set, which bots cannot provide.
  • Footnote auto-numbering with anchor links is not implemented; footers are plain blocks for now.
